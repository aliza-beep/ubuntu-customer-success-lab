# Hybrid Learning and Ownership Checklist

Use this checklist to turn the prepared project into work you understand and can demonstrate.

## 1. Inspect the repository

- [ ] Explain the purpose of every top-level folder.
- [ ] Identify which files are technical, customer-facing, and executive-facing.
- [ ] Read the disclosure in the README and keep it in the public version.

## 2. Run the Ubuntu scripts yourself

- [ ] Use `chmod +x scripts/*.sh` and explain why execute permission is required.
- [ ] Run `./scripts/system-health-check.sh` in Ubuntu/WSL.
- [ ] Explain the output for operating system, memory, disk, network, services, updates, and Ubuntu Pro.
- [ ] Run the support-information script.
- [ ] Extract and inspect the bundle before sharing or committing anything.
- [ ] Confirm generated bundles remain excluded by `.gitignore`.

## 3. Make meaningful personal edits

- [ ] Rewrite the README introduction in your own voice.
- [ ] Add one troubleshooting lesson based on your actual WSL experience.
- [ ] Improve one customer message while preserving accurate claims.
- [ ] Change one dashboard action or risk and update every related file consistently.

## 4. Test the customer story

- [ ] Explain why the health score is 76.
- [ ] Explain why no critical ticket does not automatically mean the account is healthy.
- [ ] Describe what evidence would move the score above 85.
- [ ] Explain when the CSM should involve Support, Sales, Product, or leadership.

## 5. Test the dashboard

- [ ] Open `dashboard/index.html` in a browser.
- [ ] Filter tickets by Open, Monitoring, and Resolved.
- [ ] Open the health-score calculation.
- [ ] Use the simulated onboarding button and explain that it does not alter real customer data.
- [ ] Check the page at desktop and mobile widths.

## 6. Prepare GitHub evidence

- [ ] Capture a dashboard screenshot after restoring the baseline 18/25 scenario.
- [ ] Capture a terminal screenshot with no secrets or tokens visible.
- [ ] Review all files for personal, customer, credential, or machine-sensitive information.
- [ ] Commit in logical stages rather than one unexplained upload.

## 7. Practise the five-minute demonstration

- [ ] Deliver the presentation without reading every line.
- [ ] State what was simulated and what was personally tested.
- [ ] Answer: “What would you do differently with a real customer?”
- [ ] Answer: “Why is this a Customer Success project rather than only a Linux project?”
